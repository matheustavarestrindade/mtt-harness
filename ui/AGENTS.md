# UI contributor rules

- Usage charts use the supplied shadcn Chart container/tooltip and LayerChart renderer. Keep the renderer lazy and release it when the view closes. Use the shadcn range calendar for dates; the server's date range is inclusive UTC, not local time.
- Usage tokens are uncached `Input + Output`, with reasoning already in output. Cache has its own metric. Preserve null prices versus explicit zero and separate currencies. Graphs use API aggregates or documented plugin counters; never fabricate daily history, key attribution, or convert cumulative counters into trends. Top-model limits must retain remaining usage in `Other models`; provide exact accessible data tables.

- Healthy session view WebSockets supply authoritative state and live events. Do not poll session, queue, task, or usage status while connected. The 5-second HTTP state fallback is only for disconnection. Use bounded history pages, never the full messages endpoint, and respect history/model-selection revisions plus covered event cursors. Preserve unchanged message identities and media Blob URLs. New attachment bytes/MIME/URL replace and revoke the old resource; unrelated updates must not reset playback. Workspace errors must describe server paths without assuming Docker.
- History starts at 50 messages and uses a sliding 150-message/8 MiB data window, with one oversized message kept intact. Load older/newer pages at the scroll edges, preserve a real visible anchor, and reduce the window on return to the bottom. Dispose media, xterm instances, and process sockets on eviction. Keep latest-response usage separate from the visible page. Bound auxiliary event/model/process/receipt caches and use sparse tool-owner metadata instead of loading all old calls.
- An upward wheel, touch, keyboard, or scrollbar movement pauses following immediately, including movements under 100px. Resume only at the actual bottom or through Latest; fence delayed scroll callbacks and keep the pause across same-session history revisions. Queued messages use one inline Queued label and cancel X; no duplicate queue panel or Message accepted label. Retain previews after cancellation failures and fence acknowledged cancellations against stale state frames.
- Restore queued text/roles from the authoritative QueuedMessages view snapshot, not browser-persisted receipts or guessed user roles. Keep bounded previews distinct from full queued input; Show full message reads the authenticated pending-message route on demand, rechecks session/membership/cancellation, and uses the bounded receipt cache. Runtime queue data is not a user card. Test reload/reconnect, cross-client messages, cancellation, and late body reads.

- Providers is a compact responsive grid. Default cards show only the provider name, authentication/status summary, and Configure/Models buttons. Key forms, sign-in controls, disconnect, and key links belong behind Configure; model names, pricing, reasoning, and refresh belong behind Models. Do not render or fetch closed catalogs just to populate the settings overview. Reuse ProviderCard, keep 44px controls, preserve model access and pending OAuth when a card collapses, and abort/fence stale catalog reads.

- Below 1024px, the top bar contains only Open navigation, the workspace name, and the model/effort line. The navigation drawer owns labeled Tasks, Memory, Session activity, and Settings actions; New session stays above its session list. Opening an action closes navigation before showing its panel/dialog. Closing that view restores focus to Open navigation. Preserve drafts and the Session settings cog beside Send. Desktop toolbar actions remain available at the navigation breakpoint.

- Composer attachments follow the current model's `Input` metadata, never model names or `Output`. Empty input metadata defaults to text. The provider protocol also gates audio: the current Responses adapter has no audio input. Keep session drafts isolated, abort file reads and revoke object URLs on removal/deletion/disconnect, retain uploads after a rejected submission, and clear only accepted items. A failed refresh after `202` must not turn acceptance into a retryable upload. Recheck model compatibility at Send; switching models must not silently discard files.
- The paperclip opens the shadcn `AttachmentMenu`, not a file picker directly. Always show Images, Documents, Video, and Audio; unsupported options stay visible with `aria-disabled`. Each enabled option opens a category-specific file picker. Documents includes UTF-8 text formats when the model accepts text and native document formats only when it accepts file input. Keep 44px menu rows and keyboard/focus behavior.
- Attachment limits are 8 files, 10 MiB original bytes per message, and 512 KiB per UTF-8 text file. The final JSON request must fit the API's 16 MiB limit. Preserve file bytes and names. Text attachments use text content with a filename header; no OCR, extraction, compression, transcoding, or silent truncation. Support file selection, drop, clipboard images/files, attachment-only messages, and queued media previews. Keep the empty composer one line, even when its placeholder would wrap. Only render safe media types/URLs; use object URLs with cleanup for inline data and force file downloads rather than executing active documents.

- Sidekick workspace controls live in Settings → Sidekick, with a Tasks-panel shortcut. Reuse the generic plugin panel state and shadcn selectors. Show worker costs separately from hint-input counters, preserve unknown prices, and fence old workspace responses. File and memory retrieval belong to the harness plugin, not the UI. Counters distinguish already-present request context from previously delivered source versions.
- Sidekick notes use compact collapsed chat disclosures from the session plugin-activity API, including open child-agent previews. Place them by their exact saved message/tool-result anchors; group missing anchors under earlier context. Render note text safely and references as text, without the agent instruction envelope, invented tool calls, or extra chat messages. Preserve open/scroll state, bound cached pages, and fence old reads on navigation/history changes. Existing model.call/lifecycle/reconnect signals drive refresh. Usage displays use the harness's uncached `Input` field directly. Worker token totals are `Input + Output`; show `CacheRead` and `CacheWrite` separately. Reasoning is a subset of output. Apply this to Memory, Sidekick, instruction recovery, and Settings → Usage. Keep checkpoint reduction estimates and full context measurements distinct from these usage totals; cached tokens still occupy model context.

- The sidebar always shows the selected workspace's sessions. The compact top workspace button opens a shadcn DropdownMenu containing workspaces and a New workspace action; it must never navigate to another sidebar page. Choosing a workspace closes the menu and keeps the mobile navigation drawer open until session selection. Selecting the current workspace preserves the chat and draft. Session rows are single-line, 32px for fine pointers and 44px for touch; model details stay in the title tooltip. Keep the sidebar free of promotional copy.
- The workspace menu's Unlink workspace action uses the backend unlink endpoint, not instance stop or session deletion. Confirm the target path and state that files/folders and saved data are kept. Keep 409/error responses in the dialog. Remove a reference only after success, fence stale workspace/session/model reads, close its active observers, replace its URL, and select another workspace or show the empty state. A delayed unlink must not change a different selected workspace or its draft. Unlinking never sends file-edit or conversation-delete requests.

- The Instructions settings section configures `spaced_repetition` through existing plugin endpoints. Reuse `WorkspacePluginPanelState` for plugin polling and stale-response fences, and shadcn `SelectField` for dropdowns. Show workspace recovery usage separately from reminder-input counters; reminder input is already billed to the chat. The Memory panel shortcut must work on desktop and mobile. Settings navigation must keep all sections reachable on narrow screens.

- Model selectors use `molecules/ModelCombobox.svelte`, composed from the generated shadcn-svelte Command and Popover primitives. Group and sort options by provider, show friendly model names without appended IDs or capability warnings, and keep IDs only as values/search keys. Preserve distinct selections when providers share a display name, unavailable saved values, optional empty worker selections, and controlled API confirmation/failure behavior. Use `molecules/SelectField.svelte` for reasoning efforts and other enumerated settings. Action menus use shadcn DropdownMenu. Keep 44px controls, bounded scrollable menus, wrapped long options, labels, search focus, Escape handling, and focus restoration after saves.
- SelectField keeps real values in client state and API requests; its internal option encoding also supports the empty-string model default. Controlled model/effort changes must wait for the owner to accept the change, including smaller-context confirmation and API failures. Disabled options need `aria-disabled`; a saving state must not lose keyboard focus or steal it back after user navigation.

- Keep the composer compact at one line, with automatic height growth up to 192px and internal scrolling beyond that. Preserve caret insertion, IME handling, queued submissions, draft restoration, and resizing when the available width changes.
- Keep notifications below the global header and the desktop Memory panel header. Use separate top and horizontal offsets on mobile so toasts cannot block navigation controls or become too narrow.
- Navigation can collapse on desktop; its header control must remain reachable. The right Memory panel uses workspace plugin settings/statistics from the existing API and becomes a drawer below 1280px. Poll only while visible, cancel stale reads/writes on scope changes, show pending plugin transitions, and keep errors local to the panel. Counts must distinguish current memory heads from versions and retained history. Costs retain currencies, explicit zero, estimates, and unknown prices; output already includes reasoning. Layout preferences contain no credentials or message text.

- This directory is a standalone HTTP/WebSocket client of the harness API. Do not modify Go code, API contracts, database schema, root runtime configuration, or root Compose services for UI convenience without explicit user permission.
- Tool details prioritize content: icon-led input/output rows with accessible region names, paths before options, compact commands and duration metadata, and minus/plus/arrow replacement previews. Do not show language/type banners, redundant Find/Replace with headings, or a Call prefix before the call ID. Put return settings and secondary parameters behind Tool options; use a small shared ContentActions menu for copy/download instead of a reserved toolbar above every snippet. Preserve literal source text, syntax highlighting, bounded previews, keyboard access, and 44px touch targets.
- Workspace/session/agent navigation uses URL query parameters workspace/session/agent, containing IDs only. Refresh and browser Back/Forward restore the selected root conversation and optional focused child through existing APIs. Keep credentials and API connection preferences out of URLs, preserve unrelated query/hash values, and retain drafts across in-app navigation. Fence late navigation reads, normalize child/session-only links, and replace stale URLs after deletion. Do not silently open a different session for an invalid workspace/session pair or create data while resolving a route.
- Tool arguments/results use bounded labeled fields, lists, tables, and ordered file-action sections rather than raw JSON dumps. Preserve source/code values and offer original data through copy/download. Bash and process_output use lazy xterm.js views. A live terminal sends raw bytes, input, resize, and Ctrl-C over its process socket. Saved output is read-only. Bind ProcessSpec.ToolMessageID + ToolCallID within the selected session; never guess from commands or reused call IDs. Only open views own output sockets. Preserve raw PTY bytes and separate pipe UTF-8 decoding, detect offset gaps, bound buffers/scrollback, and preserve manual scrolling. Closing a view frees its resources without killing the process; exit disables input and closes the socket. Keep stdin out of chat history. Verify real TTY detection and interaction, not just colored fixture strings.
- Process Runtime notices are agent data, not ordinary chat bubbles. Project only the exact harness process envelope into the owning bash tool, preserving the original API messages. Runtime source IDs take precedence; old wait:false calls may use their exact process-ID startup receipt. Do not guess from commands/timestamps or hide unrelated Runtime/user/assistant content. Unlinked notices coalesce into one collapsed process-output section. Keep saved exit output usable after buffers expire. ANSI styles also render inside structured result fields/tables through lazy ANSIUp plus DOMPurify; input values remain literal. Verify rendered foreground/background colors rather than only the absence of escape codes.
- A process notification can contain stderr alone and must not replace actual bash output. Open the retained process stream for completed background calls as well as running calls. Prefer captured stream bytes, then the saved tool result; use notifications only as fallback data. Keep a saved inactivity tail and its later completion output separately when no full buffer survives. A failed reconnect must preserve already-captured output and ANSI state. Verify colors in stdout and stderr before exit, after reopening, and after refresh. Terminal colors use a minimum contrast ratio of 4.5 for readability; command output without ANSI sequences stays plain.
- Interactive xterm views use normal input mode by default: xterm 6 suppresses `insertText` IME events when `screenReaderMode` is true. Keep the Terminal actions accessibility override, and verify Unicode/IME input as well as ASCII keys and Ctrl-C against a real PTY.
- Keep UI dependencies, build output, development proxy, fixtures, tests, and documentation in this directory. The Vite proxy adapts browser access; it adds no harness business logic.
- Settings → Watchers is workspace-scoped. Consume the backend's `Schema.JSON` tool catalog/default definition, preserve explicit tool-operation grants, and keep model choices in the workspace catalog. Activity uses `plugin.activity` on the existing session socket and read-only plugin pages; worker reasoning is not chat content. Hide a watcher runtime envelope only when its exact run IDs have corresponding activity entries. Keep editor, preview, and activity responses fenced across workspace/session changes.
- Use Svelte 5 runes (`$state`, `$derived`, `$effect`, `$props`) and TypeScript. Keep transport code, client state, and visual components separate.
- Ordinary HTTP origins, including Tailscale addresses, must support client actions. Use `atoms/identifiers.ts::createClientID` for local IDs: `crypto.randomUUID` requires a secure context, while `crypto.getRandomValues` does not. Verify creation and duplication with `randomUUID` unavailable, and check the actual HTTP deployment rather than only localhost.
- Watcher configuration uses shadcn Select in multiple mode for Run on, DropdownMenu checkbox items and operation submenus for tools, Switch controls for enable states, Tooltip for field help, and Tabs for Watchers/Usage/Activity. Use clear General, When to run, Review input, Tool access, and Execution limits sections. Explain `{last_context}` separately from the context-growth interval.
- `SettingsPageTitle` owns the title, icon, description, and trailing-action layout for every Settings page, including Connection, General, Instructions, Sidekick, Watchers, Usage, and Providers. Use an 18px heading beside a 20px icon with a 12px gap. The 14px description below the title must start at the page content's left edge, with zero icon-width indent; only the heading text is offset beside the icon. Do not nest the description in the heading text column or add page-specific heading markup, hero icons, centering, or width caps. Settings owns the common page inset. The original Sidekick footer remains the footer reference; Instructions and Watchers use `PluginPanelFooter`. Preserve 12px navigation text, 14px action text, and normal padding/word spacing.
- Use supplied shadcn/Bits UI controls: `Tabs` for Settings pages and watcher tabs, `Collapsible`/`Disclosure` for expandable content, `Toggle`/`ToggleGroup` for toggle actions, `Checkbox` for checked options, and the shared `Button`/`Input`/`Textarea` primitives. `npm run check:components` rejects raw control tags outside `atoms/ui`. Native media and content HTML remain appropriate for their browser behavior.
- Tab orientation selectors must use each list/trigger's own `data-orientation`, so a vertical Settings tab list cannot change a nested horizontal watcher tab list. The 44px watcher triggers need a 50px track with 3px padding on both sides. Verify selected-tab bounds, not only font size or labels.
- Bits UI 2 keeps children mounted in hidden `Tabs.Content` and `Collapsible.Content`. Gate expensive content with the selected tab/open state so closed views release requests, Blob URLs, media, xterm instances, and sockets. Hidden file inputs use `Input type="file"` with `class="hidden"`; do not combine `sr-only` with the input primitive's full-width sizing.
- Check shadcn registry output against the installed Bits UI version. The current Bits UI 2 primitives expose `data-state` and `data-orientation`; generated `data-checked`, `data-active`, or `data-horizontal` styling must be adapted to those actual attributes. Keep behavior in the library primitives.
- Use descriptive operation names in application code, such as `sendMessage`, `cancelCurrentTurn`, `loadProvidersAndModels`, and `runProviderAction`. Install the root formatting hook with `../scripts/install-hooks`; it uses this directory's Prettier configuration and dependencies for UI code.
- Use `src/lib/atoms`, `src/lib/molecules`, and `src/lib/organisms`, with imports pointing downward. Atoms contain wire types, pure helpers, icons, and shadcn primitives under `atoms/ui`. Molecules contain composed controls, HTTP/WebSocket clients, and browser storage. Organisms coordinate state, workflows, navigation, and the workbench. `App.svelte` stays a short entry point.
- Atoms must not import molecules or organisms. Molecules must not import organisms. `npm run check:layers` verifies these rules, including Svelte script imports. Keep shadcn generation paths aligned with `atoms/ui`.
- Use lucide-svelte for icons and svelte-sonner for notifications.
- Visual style: clean black and white using shadcn's neutral palette. The standard slate palette is also acceptable when requested. Do not invent a colored brand theme without explicit user approval. Use shared semantic color tokens, including surfaces, navigation, controls, and notifications; avoid hardcoded accent colors in components.
- Live Thinking headers show a bounded plain-text preview from provider-exposed reasoning, preferring the latest complete heading; never invent reasoning status or expose private continuation data. Keep full reasoning in the existing collapsed disclosure and preserve its open state through persistence. Use the shared CSS-only ActivityIndicator for active thinking and session progress, honor reduced motion, and stop it on completion/cancellation/failure. Session progress replaces the active session's leading sidebar icon, with a compact header fallback when navigation is hidden. It must not add a row to conversation output or visible “Harness is working” text. Keep the accessible Processing label and hide the session loader during permission waits.
- Thinking, assistant response text, and each tool call/result are separate sibling sections. Their backgrounds are transparent, showing the UI background. The shared section style owns padding and the page-background-colored bottom separator. Tool headers stay borderless. Only expanded tool details get a subtle neutral surface and outer border, with a line between Input and Output. Do not wrap the sections in another painted card or add nested cards around code, CSV, Markdown, or attachments. Use a neutral leading chevron for Thinking and amber for tools.
- Keep the transcript compact and square-edged with minimal padding. Preserve user messages' lighter background and slim blue left bar. Assistant content is transparent, with no avatar or role label. Section separators use the page-background color. Keep clear space between an expanded header and Input so labels cannot overlap. Reveal timestamps and message actions on hover or keyboard focus. Keep runtime/system source labels distinct. The blue user bar and amber tool chevron are explicitly approved color accents.
- Follow the wire contracts in `../routes.md`. Most domain responses have PascalCase keys; write request DTOs explicitly. Normalize nullable lists at the client boundary.
- Show `0.0` cost for loaded usage with zero calls/tokens and no cost records. Keep the loading placeholder for missing statistics, preserve explicit monetary values, and show `Unavailable` for recorded usage with no price data.
- Footer token figures belong to the selected session's latest saved assistant response with provider usage, independent of the visible history page. Do not skip an unknown latest report to show older numbers. Last context = uncached input + cache read + cache write + output; output includes reasoning once. Cache hit = cache read / total input, unknown for zero input. Use LatestResponse metadata and its recorded model identity; never infer a model limit from the current selection after a switch. Keep Total conversation/child-agent cost and estimate markers. Full cumulative accounting remains in Settings → Usage. Never run compaction or estimate context from UI history bytes for this display.
- The Tasks control (desktop header or mobile navigation drawer) opens per-session TODO/DOING in the right-side panel, sharing the same space with Memory. Small screens use a drawer. TaskPanel owns the panel layout and scroll area; TaskProgress renders the bounded session state. Never put the task card back above the composer. Empty state shows no active tasks. The harness owns completion clearing; the UI must not invent progress or mark items done. Filter reads/events by session and revision so late data cannot revive cleared tasks. A task-state read error must not remove the conversation or draft.
- Child agents use fixed-height panels within the parent conversation and sidebar trees from Session.Parent. Selection preserves the parent draft; nested agents reuse the panel. View snapshots include direct activity, so Completed:false alone never proves work. Bind stored ParentMessageID/ParentToolCallID, with legacy ordered-event origins from the API; do not guess from task text. Open history only for visible previews, use metadata-only sockets for closed active agents, and release inactive streams. Preserve failed/cancelled/unknown status, scroll/collapse state, and bounded history on scope changes. Keep focused or truly unlinked runs reachable without rendering every offscreen historical agent.
- Model selectors must retain all models returned for the connected providers or selected instance. Do not silently hide models based on capability flags. Display the optional model `Name` alone; when absent, fall back to the model ID without its provider prefix. Always submit the full, unchanged ID.
- Workspace forms start with an empty path and a generic server-path placeholder. Do not prefill `/workspace`, recommend a test provider, or assume Docker in error text. Explain literal `~` input only when entered; never substitute the browser's home directory or guess the server home path.
- Current-session configuration opens from one cog icon beside Send in the composer. Keep Model and Thinking fields inside the Session settings dialog, not in a permanent row below the chat. Show smaller-context confirmation inside the same dialog. Preserve drafts, history, and shared stale-read protection for model/effort updates. Keep global harness settings separate. Report session-setting outcomes inline instead of stacking success toasts.
- Cancel obsolete reads when the selected session or connection changes. Never let an old request overwrite a newer selection. Dispose timers and sockets when the client disconnects.
- Composer shortcuts: unmodified Enter submits; Shift+Enter or Command+Enter inserts a newline (Ctrl+Enter also inserts a newline). Do not submit IME confirmation, blank drafts, repeated held Enter events, or another message while submission is pending. Session deletion must call the real API, retain unrelated drafts, remove the returned descendant IDs, and prevent stale requests from restoring deleted entries.
- Render API/model content as text or sanitized markup. Keep the API token in tab-scoped session storage; never put it in frontend environment files, repository fixtures, logs, or persistent URLs.
- Build mobile-first. Use a drawer for navigation on narrow screens, dynamic viewport height and safe-area padding, labeled controls, visible focus, and scrollable code blocks. Check both 390px mobile and desktop layouts.
- Do not imply that a UI-only operation deletes server data. Show real API errors and document unsupported features instead of inventing endpoints.
- Commands: `npm ci`, `npm run check`, `npm run build`, and `npm run test:e2e`. Product documentation follows the root STE rules.
